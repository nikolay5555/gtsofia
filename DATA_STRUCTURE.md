# GT Sofia transport data model

Генерираните данни следват компактния модел, използван от `Dimitar5555/sofiatraffic-schedules`: основният график е разделен на `stops`, `routes`, `directions`, `trips` и `stop_times`.

## Основни файлове

### `data/stops.json`

Всеки запис е във вида:

```json
{
  "code": "0328",
  "coords": [42.70669, 23.29992],
  "names": {
    "bg": "бул. К. Величков"
  }
}
```

Повърхностните спирки използват четирицифрен код. Метростанциите запазват `M`-префикса във вътрешния stop code.

Имената за спирки са с приоритет от OpenStreetMap по същия модел като проекта на Димитър: OSM е авторитетният източник при съвпадение по код, а CGM/GTFS остава fallback за спирки, които липсват в OSM. `name:en`, кратките/пълните имена и `request_stop` също се запазват, когато са налични. Имената на направленията/дестинациите се извеждат от името на крайната спирка; GTFS headsign е fallback само при непълно съпоставяне.

### `data/routes.json`

Линията има един основен `type` и по избор вторичен `subtype`:

```json
{
  "cgm_id": "A224",
  "route_ref": "N1",
  "type": "bus",
  "subtype": "night",
  "text_color": "#FFFFFF",
  "bg_color": "#000000"
}
```

Основните типове са `metro`, `tram`, `trolley`, `bus`. Подтиповете са `school`, `temporary`, `night` и никога не заменят основния тип.

Метролиниите са публично `1`, `2`, `3`, `4` — без `M` в `route_ref` и във визуалния номер на линията.

### `data/directions.json`

Едно направление е един уникален подреден списък от спирки:

```json
{
  "code": 69,
  "stops": ["2829", "6430", "2079"],
  "destination": "пл. Възраждане",
  "shape_id": "A4518"
}
```

### `data/trips.json`

Логическо пътуване обединява курсовете по `(cgm_id, direction, is_weekend)`. Полето `source_trip_ids` пази оригиналните GTFS trip IDs, така че realtime съпоставянето да не губи точност.

### `data/stop_times.json`

Времената са цели минути от началото на денонощието, както в модела на Димитър. `null` запазва липсващо време при частични направления.

## Допълнителни файлове

- `data/calendar.json` — компактна дата/услуга информация за клиента.
- `data/shapes.json` — геометрията на маршрутите, отделно от основния schedule модел.
- `data/meta.json` — версия, източник, дата и брой записи.

Старият `data/transport.json` не се генерира и не е част от runtime модела.

## Виртуални табла

За surface транспорта frontend-ът не избира „realtime или static“. Всички налични static курсове и realtime курсове се обединяват в един списък. При наличие на общ `source_trip_id` realtime ETA заменя точно съответния static курс; при липса на идентификатор се използва ограничен fallback по линия, направление, дестинация и scheduled време. След това кандидатите се сортират по реалното ETA и се показват първите четири.

Наблюдаваните realtime курсове се запомнят за кратко по спирка и конкретен GTFS trip. Това предотвратява повторното появяване на static часа, когато vehicle update изчезне от GTFS-RT непосредствено след като превозното средство е пристигнало. За метрото realtime изобщо не се използва: показва се само static разписание.

При пристигания под една минута интерфейсът показва `0 мин.` вместо отделно състояние „Сега“. При 60 секунди и нагоре минутите се закръгляват към най-близката минута.
